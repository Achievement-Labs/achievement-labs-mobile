# Mobile Xbox 360 and update routing

Android and iOS now share an offline CON/STFS/GPD editor, with native document pickers and private working copies. Open **Xbox 360 → Open exported profile**, choose a game, select locked achievements, choose offline/now/custom/reference dates, and press **Unlock selected**. This backs up, updates the game and dashboard records, rehashes and re-signs. **Export signed profile** saves a separate document for the user's console/USB workflow. The original export is read-only; **Export original backup** is also available. Mobile imports are limited to 32 MB and supported retail CON profiles with the two-level STFS layout used by the desktop editor. Other layouts fail closed.

Unlocked rows are green. Both game and achievement lists have sorting, and achievements default to locked-only. Artwork uses cached Xbox library artwork when available. Xbox reference lookup accepts a gamertag and matches exact title/achievement IDs and gamerscore; it only sends ordinary Xbox reference queries, never the exported profile. Exophase JSON/HTML import matches unique names and requires the user to confirm the game and edition. No lookup starts an unlock. Future dates, missing/ambiguous matches, damaged signatures/hash trees, overlapping file blocks and changed working copies are rejected. Imports and edits stay local. Console acceptance and subsequent Xbox synchronization still require a real device test.

The shared engine accepts no network or file APIs. A dedicated WebView hosts bundled assets with restrictive CSP; native bridges expose bounded, ordered 32 KB transfers and no account tokens. Every save verifies the previous working copy, writes a verified private backup, validates received bytes, and atomically replaces the private working file. Incomplete transfers cannot replace it. The reusable CON identity is prepared, without executing anything, from the pinned, SHA-256-verified official `desktop-preview-v0.1.0` Linux package in Achievement-Labs/achievement-labs, and must match the approved identity hash. The former fork .14 download no longer exists; `--exe` still accepts a saved copy of it. Raw generated signing assets stay ignored by Git. `mobile/tools/prepare_360.py` prepares both apps' assets.

Android and iOS app updates use **Achievement-Labs/achievement-labs-mobile** published releases (drafts, prereleases and equal/older versions are ignored). Windows updates, event JSON and the public mobile event feed remain at **Achievement-Labs/achievement-labs**.

Mobile Game Session combines presence/spoof controls and Auto Unlock while retaining separate explicit Start actions. Library shortcuts select the game for both controls; active sessions prevent switching to another game. Old spoof deep links and launch preferences resolve to Game Session.

Validation: synthetic shared-engine cases exercise imports, signatures independently through Node RSA, hash trees, totals, timestamps, immutable inputs and failed edits. A separate C# check validates mobile-generated output from a private working copy of an actual profile. Android tests cover incomplete/out-of-order transfers and backup/atomic persistence. Emulator/simulator checks run the real WebViews against a generated synthetic profile and verify native signed-save and backup/export bytes. Fixtures contain no real profile/account data.

**Add game from GPD catalog.** After opening a profile, **Load catalog** lists titles from the public, download-only GPD catalog (release assets in Achievement-Labs/achievement-labs: the index in the `gpd-catalog` prerelease and each GPD in the `gpd-catalog-N` prerelease its entry names; updaters ignore prereleases; Android follows only the GitHub release-asset redirect). The native host downloads the index (4 MB cap, last verified copy cached for offline use) and a selected GPD (8 MB cap), and rejects any GPD whose size or SHA-256 differs from the index. The shared engine converts it to the locked catalog form (`Gpd.template`: achievements, images and strings only, unlocks/timestamps/settings/sync history cleared), inserts it as a new STFS file after the last allocated block, re-signs, re-verifies every existing file and the inserted GPD, and saves through the same backed-up chunked commit. Like the desktop editor, no dashboard record is written: the game is listed as awaiting console sync and cannot be edited until the profile is signed in on a console and exported again. Optional, off-by-default contributions (Settings) export a locked copy of a profile title's GPD through the document picker and open a prefilled `gpd-contribution` GitHub issue for the user to attach it; nothing is uploaded automatically and no account token is used.
